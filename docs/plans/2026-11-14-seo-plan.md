pages that rank for the query (or its fan-out sub-queries) and contain a quotable direct answer.
No special markup gets a page in. This plan covers code only. Off-site work (Search Console,
backlinks, launch posts) stays in project.md §11 "Launch track".

## Phase 1: headings, titles, meta (highest value per line of code)

New pure module `scripts/lib/seo-copy.js` (no IO, unit-testable like `entry-schema.js`):

- `subsectionTitle(sub, entries)` → page `<title>` and `<h1>` text.
  - Use `sub.seo_title` if the subsection YAML sets it (new optional field, see Phase 2).
  - Else formula: `${subTitle}: ${n} ${noun}`. `noun` comes from the dominant `entry_type`
    (software/tool/plugin → "tools", asset-source/marketplace → "sites", tutorial/channel →
    "tutorials and channels", book → "books", fallback "resources").
  - `<title>` = that + ` | 3D Resources`, trimmed to ≤60 chars by dropping the suffix first.
  - Keep `: ` as the separator (OG splitter in `build-og-images.js` keys on it).
- `sectionTitle(section, entries)`: same pattern.
- `tagTitle(tag)`: uses display labels, e.g. `Arch Viz resources: 163 tools and sites`.
- `metaDescription(...)`: first sentence of the intro (Phase 2), ≤155 chars.

Wire-up:

- `build-section-pages.js:248` / `:208`: use the new titles for `pageTitle`, the JSON-LD
  `CollectionPage.name` (`:128`, `:162`) and OG/Twitter (they already read `pageTitle` via `page-shell.js:51-62`).
- `<h1>`: in the subsection path, after `postProcessHtml` (`:408`), replace the first
  `<h3 id="${sub.anchor}">` with `<h1 id="${sub.anchor}">` and the new h1 text. Section pages:
  same for the first `<h2>`, keeping the Edit-on-GitHub link and icon.
  Do NOT shift all heading levels: `assets/css/style.css` styles `h3[data-mirror]`
  (`:1051-1084`) and `h2#contents`, so a global shift breaks mirror blocks.
- Tag display labels: the map lives client-side in `assets/js/filter.js:70`. Move it to a
  JSON file both sides read (e.g. `assets/data/tag-labels.json`, copied to `_site/` by
  `build-html.js`), or duplicate it in `scripts/lib/` with a parity test. Prefer the JSON file.
  `scripts/lib/studios.js:20` has its own label map for studio disciplines; leave it alone.

Tests (`scripts/lib/seo-copy.test.js`, auto-picked by `scripts/run-tests.js`):
- title ≤60 chars for every real subsection (load via `seo.subsectionPages()`).
- no `—` and no banned word in any generated title/description.
- every built section/subsection page has exactly one `<h1>` (add to `scripts/check-built-links.js`
  or a small post-build check in `build.sh`).

## Phase 2: answer-first intro on every section/subsection page

AI Overviews quote short passages that answer the query. Add a 2-4 sentence intro block above
the table, built from data so it scales to 160 pages and stays current.

`seo-copy.intro(sub, entries)` returns plain-text sentences. Illustrative shape (counts and names
not taken from the data):

> 55 AI tools that generate 3D models from text or images. 18 are free or have a free tier,
> 12 are open source. Free options: Hunyuan3D, TripoSR, 3DTopia. Runs in the browser: 3D AI
> Studio, Meshy, Tripo.

Inputs, all already in the data:
- counts by `license` (Free / Freemium / Open Source / Paid),
- counts by `tags.platform`, `entry_type`,
- up to 5 names per "free" / "open source" / "web" bucket. Order by an explicit editorial
  `picks` list when present, else by `url_status: ok` first, then name. (`priority` is set on
  only 1 entry, and `quality-score.js` ranks URL hygiene, not quality, so neither can pick favourites.)

Optional editorial overrides on the subsection object in `data/NN-<section>.yml`
(next to `slug`/`title`/`description`), all freeform strings, no enums:
- `seo_title`: hand-written title for the ~30 subsections with real search demand.
- `intro`: one hand-written sentence that replaces the generated first sentence.
- `picks`: list of entry URLs to name first.
Check `scripts/validate.js` / `catalog.loadSection` for unknown-key handling before adding,
and document the fields in project.md §4.

Markup: `<section class="page-intro"><p>…</p></section>` directly under the `<h1>`. Escape all
names. Same text, trimmed, becomes the meta description and `CollectionPage.description`.

Below the intro, a "Narrow it down" link row to the tag pages that intersect this subsection
(top 5 tags by count among its entries, only tags whose page is indexable). Internal links
help crawl depth and give Google the "free X" / "X for Blender" sub-query pages.

Tests: intro for every real subsection has no `—`, no banned words, ≤320 chars, and mentions
the entry count that `seo.subsectionPages()` reports.

## Phase 3: intersection pages for "free X" / "open source X" queries

New page type from the existing enumerator so pages and sitemap can't drift
(`seo-pages.js` header comment):

- `seo.licensePages()` → `/sections/<section>/<sub>/free/` and `/open-source/` where the bucket
  has ≥ `THIN_THRESHOLD` entries. Consider a higher bar (5) for these; they're near-duplicates
  of the parent otherwise.
- Title: `Free ${subTitle} tools: ${n} options`. Intro from Phase 2 restricted to the bucket.
- Canonical to itself; parent links to it from the "Narrow it down" row.
- `build-sitemap.js` adds them from the same enumerator; analytics context
  `pageType: 'subsection'` plus a `data-license` attr, or a new `page_type` value (update
  project.md §8b if so).

Do this only after Phase 1-2 have shipped and Search Console shows impressions for
"free <subsection>" queries. Otherwise it's 100+ pages of guesswork.

## Phase 4: freshness and structured data

- `build-sitemap.js:71`: per-URL `<lastmod>` = max(`added_at`, `url_last_verified`,
  `pricing_last_verified`) over that page's entries; homepage and hubs = max over all.
  `seo.subsectionPages()` already returns `entries`; tag pages have them from `tagPages()`.
  Drop `<changefreq>` and `<priority>`: Google ignores both.
- `CollectionPage` JSON-LD: add `dateModified` (same value) in `buildSectionJsonLd` /
  `buildSubsectionJsonLd`.
- Visible "Updated YYYY-MM-DD" under the `<h1>` with that per-page date (the footer at
  `page-shell.js:118` shows the site-wide git date; keep it).
- Homepage `Person` node (`build-html.js`): add `sameAs` (GitHub profile, repo, any socials) so
  Google ties the site, repo and author into one entity. Add `publisher` on `WebSite`.
